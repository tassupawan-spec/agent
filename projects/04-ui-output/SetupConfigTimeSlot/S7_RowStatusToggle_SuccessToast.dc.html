Annotations — S7 Status toggle + toast

[proposed] token ที่ใช้: --color-success-* (ยังไม่ได้ verify กับ production screen จริง — DESIGN.md §0)
Trigger
คลิก toggle ในคอลัมน์ "สถานะ" ของแถวใดก็ได้ในตาราง S1 → สลับค่าทันที (optimistic, ไม่มี confirm dialog) และ summary KPI (Capacity รวม, รอบจัดส่งที่เปิดใช้งาน) คำนวณใหม่ทันทีที่การ์ด "สรุปการตั้งค่า"
Toast only on ปิด → เปิด
PO decision: แสดง success toast เฉพาะตอน toggle จาก "ปิด" เป็น "เปิด" (activate) เท่านั้น การ toggle "เปิด" → "ปิด" (deactivate) ไม่ต้องมี toast ใดๆ — ไม่มี toast ที่ page-level "บันทึก" เช่นกัน (ยืนยันแยกต่างหากใน S8)
Toast anatomy — new component
ไม่มีอยู่ใน DESIGN.md §10 (มีแค่ --z-toast token ที่กันไว้ล่วงหน้า). ออกแบบจาก token ที่มีอยู่ทั้งหมด: การ์ดขาว --surface-raised, --shadow-lg, --radius-sm, แถบสีซ้าย --status-success-icon หนา --border-width-thick — สอดคล้องปรัชญา "status เป็น icon ไม่ใช่ fill สีทึบ" ที่ใช้กับ status ทั่วทั้งระบบ. ตำแหน่ง bottom-right, auto-dismiss แนะนำ 4 วินาที, มีปุ่มปิดเอง, มี role="status" aria-live="polite" สำหรับ screen reader
Visual cue on the toggle itself
Toggle ที่เพิ่งเปิดมี halo สีเขียวอ่อนชั่วขณะ (--duration-normal) เป็น micro-feedback เสริม toast — เป็นการตกแต่งเชิงฟังก์ชัน ไม่ใช่ animation บน data load จึงไม่ขัดกติกา forbidden ใน CLAUDE.md §3.7
Contrast check
Toast text --text-primary #212121 บน --surface-raised #ffffff → 16.1:1 ✅. ไอคอน check --status-success-icon #2e9e6b บนพื้นขาว → 3.2:1 ✅ (≥3:1 สำหรับ icon/non-text) แต่สถานะยังสื่อด้วยข้อความเต็มประโยคเสมอ ไม่พึ่งไอคอนอย่างเดียว
