PO Decisions (resolved 2026-09-28)

  1. Delete (ลบ) — ปฏิเสธสำหรับหน้าจอจริง. Hard-delete ที่พบใน prototype ต้องไม่ถูกนำไปใช้จริง เพราะกระทบข้อมูล Report ที่อ้างอิง Slot เดิม แนะนำใช้ toggle สถานะแทนการลบ — ยังเหลือ 1 คำถามที่ต้องยืนยัน: เอาไอคอน "ลบ" ออกทั้งหมด หรือคงไว้แบบมีเงื่อนไข? (blocker เดียวที่เหลือก่อนส่งต่อ ui-designer)
  2. Validation ใน Modal เพิ่ม/แก้ไข เวลารอบจัดส่ง — แก้ไขแล้ว. ต้อง check overlap กับ Slot Time และ Load Time ของแถวอื่นตาม API spec แล้วแสดง error ที่มองเห็นได้เมื่อซ้อนทับหรือฟิลด์บังคับว่าง
  3. Toggle "สถานะการใช้งาน" ระดับ Pool ไม่ตอบสนอง — ยืนยันแล้วว่าเป็นข้อจำกัดของ prototype เท่านั้น หน้าจอจริงต้องใช้งานได้
  4. ปุ่ม "ย้อนกลับ" ไม่มีผล — ยืนยันถูกต้องแล้ว ไม่ต้องแก้ไข (ปลายทางอยู่นอกขอบเขตไฟล์นี้)
  5. ไม่มี toast หลัง Save — ยืนยันถูกต้อง แต่เพิ่มข้อกำหนดใหม่: toggle สถานะแถว ปิด→เปิด ต้องมี success toast
  6. Filter panel — ยืนยันแล้ว: คลิก "ตัวกรอง" ซ้ำ = ปิด panel เฉยๆ, ต้องกด "ใช้ตัวกรอง" ถึงจะ apply จริง
  7. เมนู sidebar อื่น ๆ นอกจาก "ข้อมูล Pool" เป็นเพียง stub ที่คลิกแล้วไม่มีผล — มีเพียงหน้าจอเดียวที่ทำงานได้จริงใน bundle นี้
  8. สวิตช์ "มีข้อมูล" / "ไม่มีข้อมูล (Empty State)" เป็นเครื่องมือของผู้สร้าง prototype สำหรับสลับดูสองสถานะ ไม่ใช่ปุ่มจริงที่ผู้ใช้งานจะเห็นในระบบจริง — ไม่นำไปออกแบบเป็นปุ่มจริง
  9. Side effect เขียน clipboard ที่พบตอนคลิก "เพิ่มเวลารอบนัดหมาย" — น่าจะเป็นโค้ด debug/dev-helper หลงเหลือใน prototype ไม่มีจุดประสงค์ทางธุรกิจ แนะนำให้ทีม engineering เอาออก ไม่ต้องนำไปสร้างซ้ำในระบบจริง
  10. (2026-09-28) เพิ่ม Create-Pool sub-flow (S2 / S2-1 / S2-2 / S2-3) — ไม่มี prototype อ้างอิง. เป็น requirement ใหม่จาก PO ทั้งหมด ต้องออกแบบจาก DESIGN.md token ล้วนๆ ยังเหลือ 2 คำถามเปิด: ฟิลด์ที่แน่ชัดของ S2-1 (รหัส Pool เป็น system-generated หรือ user กรอกเอง) และรูปแบบของ S2-3 (หน้าสำเร็จเต็มหน้า vs. toast + redirect)
  11. เพิ่ม S9 (Validation + Check Overlap) เป็น node ที่ชัดเจนสำหรับ S4/S5 — เพื่อ formalize กติกาตรวจ overlap Slot Time/Load Time เดิม ให้เห็นชัดในผังว่า "บันทึก" ของทั้งสอง modal ผ่านจุดตรวจเดียวกัน
